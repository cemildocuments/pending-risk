# PendingRisk

Reproducible experiments for **Anytime-Valid Risk Auditing with Pending Labels** by Cemil Emre Yavas.

PendingRisk implements Pending-Aware Certificate Envelopes (PACE): confidence intervals for the realized average bounded loss of issued predictions under randomized label requests and arbitrary outcome-dependent completion delays. It includes four public prediction tasks, fixed predictor traces, controlled simulations, completion-policy experiments, and mathematical implementation tests.

## Reproduce the results

Use Python 3.12 and create an isolated environment:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python reproduce.py --workers 6
```

On Windows, activate the environment with `.venv\Scripts\activate` before the installation command. The replay runs on CPU. Adjust `--workers` to the available physical cores and memory; six workers fit comfortably within 2 GB for the supplied workloads. Each worker limits numerical-library threads to one.

The runner verifies frozen-trace SHA-256 hashes, executes the implementation tests, runs all four experiment suites, computes summaries, and compares the numerical outputs with the archived reference results. Numerical comparisons use absolute and relative tolerances of `1e-10`, with exact equality for categorical fields. The frozen traces make monitoring results reproducible across supported systems independently of model-refitting differences.

Individual commands are:

```sh
python tests/test_monitor.py
python run_experiments.py --suite public --workers 6
python run_experiments.py --suite synthetic --workers 6
python run_experiments.py --suite expedite --workers 6
python additional_experiments.py --workers 6
python analyze_results.py
python verify_results.py
```

## Experiment design

- Public replay: 32 distinct predictors × 2 request policies × 5 feedback regimes × 20 audit seeds = 6,400 paired paths.
- Controlled simulation: 2 loss regimes × 2 request policies × 5 feedback regimes × 1,000 repetitions = 20,000 paths.
- Completion policies: 32 predictors × 2 request policies × 2 feedback regimes × 20 seeds × 3 completion rules = 7,680 paths.
- Adaptive requests: 1,000 binary-loss and 1,000 continuous-loss streams.
- Backlog identity: 2,000 randomizations at each of five audit probabilities for a fixed 8,192-case potential-outcome table.

`experiment_config.json` records the fixed experimental settings; the implementation and runner arguments define execution. The nominal simultaneous-error level is 0.05. Checkpoints occur every 64 issued predictions and at the final prefix; summaries start at 512. `error_slow`, `correct_slow`, and `censored` impose controlled feedback mechanisms on public outcomes. These are simulated label delays, not observed operational delays.

The target is the realized issued-prefix average loss. A below-threshold declaration is not a forecast of future risk. Validity assumes correct returned labels, positive exact logged request probabilities, and independent fresh request coins conditional on the pre-request history. Empty feasible sets count as noncoverage and yield no declaration.

## Trace schema

Each compressed NumPy archive contains `loss`, `uncertainty`, `probabilities`, `labels`, `predictions`, `source_index`, `calibration_loss`, and `calibration_uncertainty`. Monitoring consumes losses only when their completion event occurs. The evaluator separately uses the full loss sequence to score coverage and to compute the explicitly labeled full-feedback oracle.

Adult preserves its original test split. Bank Marketing and Electricity use source-ordered 50%/15%/35% partitions. The Bank duration feature is removed. Gas uses batches 1–3 for fitting, batch 4 for calibration, and batches 5–10 for monitoring. Numeric and categorical preprocessing is fitted on the fitting partition only. Models are fixed during replay.

## Refit the predictors

The archived prediction traces are the canonical inputs for exact monitoring reproduction. To regenerate predictors from the public source archives:

```sh
python -m pip install -r requirements-training.txt
python prepare_data.py
python train_models.py --mode cpu --workers 6
python train_models.py --mode gpu --device auto
```

The neural-network runner selects the Metal GPU backend when available and otherwise uses CPU. `--device cpu` explicitly selects CPU. Random-forest and neural-network seeds are 11, 29, and 47; logistic regression and histogram boosting use seed 11 because the specified fits were deterministic. Model refitting may differ slightly with hardware, library versions, and numerical kernels, particularly on GPU. Refit outputs are written into `data/traces/`; use a separate extracted copy to compare refitted traces against the canonical release. Source archive integrity is checked against the recorded SHA-256 values.

## Interpreting the summaries

Each replay is first averaged over its checkpoints, then averaged over the fixed predictor collection. Paired bootstrap intervals resample the 20 shared audit-seed identifiers jointly across all compared configurations, preserving cross-condition dependence. Synthetic binomial intervals are computed separately within each 1,000-repetition cell. A maximum over cells is a descriptive worst-cell result, not a simultaneous confidence interval. Timing and peak-memory results depend on the execution system and are reported separately from numerical-result verification.

The code uses the conservative finite exponential grid described by `monitor.LAMBDAS`. Its anytime guarantee does not imply that the intervals must become informative quickly under every feedback process. The weight-priority theorem concerns the immediate **unclipped outer-envelope width** under equal completion costs.
